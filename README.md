# PORTAFOLIO DE INGENIERÍA DE REQUISITOS

**Curso:** Ingeniería de Requisitos  
**Institución:** Universidad Pontificia Bolivariana  
**Autor:** Lucas Acevedo Rubio
**Estado:** Entrega final  

## Propósito

Este repositorio organiza y conserva los principales artefactos desarrollados durante el proceso de Ingeniería de Requisitos.

El objetivo es permitir que una persona externa pueda comprender el contexto de los proyectos, identificar los artefactos generados y verificar la trazabilidad entre requisitos, historias de usuario, tareas, solicitudes de cambio, pruebas y otros elementos relacionados.

## Estructura del repositorio

### 01_AeroCrew_Manager

Contiene los artefactos relacionados con la visión y planificación del producto:

- Product Vision Board
- Backlog priorizado
- Sprint Backlog
- Tareas de ingeniería
- Visual Story Mapping
- Informe técnico

### 02_Simulador_Transmision

Contiene los artefactos de especificación y validación del Simulador de Transmisión Mecánica:

- Especificación de Requisitos de Software (SRS)
- Casos de prueba
- Walkthrough de validación

### 03_Gestion_Cambios_Prototipo

Contiene los artefactos relacionados con la gestión de cambios:

- Solicitudes de cambio RFC
- Análisis de impacto
- Actividad de prototipado
- Prototipo funcional en HTML

### 04_Trazabilidad

Contiene la matriz de trazabilidad final del proyecto.

La matriz relaciona requisitos con:

- Casos de uso
- Historias de usuario
- Tareas de ingeniería
- Casos de prueba
- Artefactos relacionados
- Componentes o módulos

También registra los metadatos de los artefactos:

- ID único
- Versión
- Estado final
- Autor o revisor
- Fecha de cierre
- Artefactos relacionados

## Control de versiones

El repositorio utiliza GitHub para conservar el historial de cambios y las diferentes incorporaciones realizadas durante la construcción del portafolio.

## Estado de cierre

Los artefactos se encuentran organizados y disponibles para consulta y auditoría de trazabilidad.
